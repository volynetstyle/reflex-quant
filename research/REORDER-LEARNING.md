# Per-consumer learning for dependency reorder

## Preregistered experiment

Baseline `3f297b7`. Use isolated source copies and the same production benchmark
adapters as the previous reorder study. The source of `read` and `exec` must be
byte-identical before bundling, and an original A/A bundle controls for process
noise. The unchanged source cannot guarantee identical optimized V8 code. See
[the earlier physical experiments](./REORDER-LOCALITY.md).

Start observing a consumer after its first expensive suffix mark or slot index.
This event can install a callback wrapper whose first measurement starts on the
next invocation. Count old unread edges recovered by the resolver after the
bounded proofs have failed. A qualifying run finishes successfully, keeps the
same set of relations, recovers at least 32 old edges and has `4k ≥ 3d`. Determine
the frontier size with an exit walk capped by `floor(4k/3)` only when all cheaper
tests qualify. Once a width is known, an unchanged set certifies the same width.
Three consecutive qualifying passes in the same resolver class arm the next
execution. One nonqualifying pass disarms, two remove the wrapper. Failure drops
the observation immediately. This selects dense same-set permutations. It
deliberately treats a large but well-ordered tail run as a cheap proof.

| Variant | Intervention | Predicted result |
| --- | --- | --- |
| Observer | Wrap and score suspected consumers, retaining the ordinary resolver | Virgin stable cases install zero observers. One-off and `swaps-nested@8` arm zero specialized passes. Local families remain within 5% of Quant. |
| Learned reconstruction | Arm the previous array-free backward-thread reconstruction for the next execution. Open it only at a first-subscriber mark. | Private `shuffle@4096` median ≤0.95 of Quant in both repetitions, stable and `swaps-nested@8` ≤1.05. The earlier 15% target still governs a production speedup. |
| Selective witness | For repeatedly indexed consumers retain one vector of exact edges. In the next run use that vector to fill and clear ordinary slots in the same order. Keep the ordinary online relocation. | Indexed `deep-shuffle@4096` median ≤0.90 of Quant in both repetitions. A settled private shuffle retains zero vector cells. Stable and `swaps-nested@8` ≤1.05. |

The witness vector is capped at 8,193 edges per admitted consumer. A nonqualifying
execution discards it. For unchanged membership, vector order can remain fixed
as the actual dependency list changes. The insertion of a new relation cancels
the vector-only cleanup path. The ordinary full-list slot cleanup can then reach
every slot. A failed or disposed consumer also drops learning state. Include
phase changes, failures, nested active slots and self-disposal in the checks.

Measure fresh processes, independent shuffled rounds and A/A within each job.
Test short and wide stability, sparse edits, repeated budget exhaustion,
private shuffle, deep shared shuffle, and a process that runs both stable and
chaotic consumers. Report useful, wasted and retained work independently of
time. Compare the first pass after a phase change separately from steady state.

## Реализация и граница переключения

На первом помеченном суффиксе или slot-index с непрочитанными рёбрами
эксперимент устанавливает обёртку через существующее поле `fn`. Текущий вызов
тела продолжается как прежде. Измерение начинается при следующем вызове.
Оба горячих входа, `read` и `exec`, побайтно совпадают на уровне исходников.
Профиль общего места вызова всё равно увидит обёртки в смешанном графе.
Поэтому `track.stable-1` и смешанный сценарий проверяются раздельно.

`k` в режиме наблюдения считает принятие ранее непрочитанного ребра после
исчерпания ограниченных доказательств. В режиме реконструкции `k` считает
нарушенные старые смежности у присоединяемых рёбер. Длинная смежная полоса
при таком счётчике добавляет только границу. Это рабочие свидетельства о
плотности, точный edit distance здесь не вычисляется. Проверка ширины
просматривает не больше O(k) рёбер и начинается только с `k ≥ 32`.
После подтверждения прежняя ширина остаётся точной при той же совокупности
рёбер. Создание связи или непрочитанный остаток сбрасывают квалификацию.

У каждого наблюдаемого потребителя собственные счётчики и снимок ширины.
Метка успешного прохода открывает следующий режим после трёх успешных
наблюдений подряд. Перед вызовом тела обёртка сохраняет контекст предыдущего
наблюдаемого потребителя. На любом выходе она восстанавливает контекст.
Отказ внутри измеряемого вызова сразу снимает обёртку. Если исключение
следует за самой первой установкой во время ещё обычного вызова, пробный
режим ждёт следующего исполнения с нулевым счётом.

Реконструкция начинает откладывать перестройку только в вооружённом вызове
при фактическом промахе с парой в голове списка подписчиков. Вектор
наоборот заранее заполняет слоты, пока потребитель занят. Этот вариант
удерживает точный набор рёбер в порядке, зафиксированном при первом
допуске, и перечисляет этот набор как при заполнении, так и при очистке.
Логический порядок продолжает определяться первым чтением и обычным
переносом. В памяти остаётся до 8193 ссылок на обученного потребителя, для
которого подтвердился индексный режим. Суммарная стоимость пропорциональна
фронтирам допущенных потребителей. Общего лимита на число таких потребителей
в этом прототипе нет. [Сборка и проверки границ](./reorder-learning-build.mjs)

## Структура и семантика

| Сценарий | Работа трекера за шаг после прогрева |
| --- | --- |
| `track.stable-1`, `track.stable-64`, `stable.wide-256` | Все варианты проходят по исходному курсору. Ноль регистраций, измерений плотности, переключений и специализированных исполнений. |
| `swaps-nested@8` | Quant и три варианта помечают в среднем 380 рёбер за шаг и переносят через глобальный resolver 2. Пробная обёртка устанавливается примерно раз в четыре шага. Все переключения, проверки ширины и новые широкие обходы равны нулю. |
| `lb.shuffle@4096` | Quant и контроль выполняют 4086 переносов. Реконструкция открывает режим раз за шаг, заменяет переносы на 4096 дописываний и 4096 починок обратных ссылок. Селективный вектор здесь занимает ноль ячеек. |
| `deep-shuffle@4096` | Селективный вектор перечисляет 4097 ссылок при заполнении и столько же при очистке. 4088 online-переносов прежнего алгоритма сохраняются. |
| `shared-chaotic.64x32` | За шаг 31 векторный проход для глубоких потребителей. Реконструкция открывается только у одного потребителя, который находит пары с головы. |

В точечном тесте четыре последовательных перестановки оставляют
специализированные счётчики на нуле. Пятая включает режим. При повторении
того же порядка вооружённый вектор ещё раз заполняет и очищает слоты,
после чего снимается. Реконструкция на том же стабильном вызове не
открывается. После второго стабильного вызова в `fn` снова стоит исходное тело. Единичный
широкий промах также заканчивается возвратом исходного тела без повышения.

Прямые проверки включают порядок и идентичность рёбер, вызываемый
`this` и предыдущее значение тела, две вложенные оценки по тем же
источникам с возвратом слотов, новый источник внутри обученного прохода,
отказ с неизменённым исключением, восстановление и самоудаление.
Дополнительные локальные проверки охватывают отказ до первого чтения
при уже занятых слотах и сохранение первой версии после записи и
повторного чтения внутри обученного прохода.
Ребро удалённого потребителя собирается GC при удержанном терминальном
узле. При свежей связи признака наличия в векторе больше недостаточно
для очистки. Обёртка использует обычную очистку по списку и снимает вектор.
Код переустановки исходного тела проверяет терминальный `fn === null`.
[Исполняемые проверки](./reorder-learning-witness.mjs)

## Точное свидетельство для sparse edit

У отложенного ребра уже есть сигнал `SKIPPED`. После успешного
наблюдения все пути принятия заменяют его действительной версией.
Значит, если обычный ограниченный поиск в подписчиках нашёл пару
с `SKIPPED`, она принадлежит непрочитанному суффиксу. Это верно и
для тега, пережившего исключение. Сам тег не используется для поиска
пары. Он отвечает на второй вопрос, была ли она уже принята в этом
исполнении.

Отдельный прототип использует это свидетельство при промахе и переносит
найденное ребро без пометки всего суффикса. При восьми вложенных обменах
около позиции 256 увеличивался только неизменный конец списка.

| Ширина | Рёбра в пометке или индексе, Quant | С проверкой `SKIPPED` | Поиски с проверкой |
| ---: | ---: | ---: | ---: |
| 1024 | 380 | 0 | 1 |
| 4096 | 1916 | 0 | 1 |
| 8192 | 3964 | 0 | 1 |

Это средние за шаги, в которых порядок чередуется. Сумма в прототипе
чувствительна к порядку, а после каждого шага проверяются связи, версии
и прежняя идентичность рёбер. В этом семействе исходная цена широкой
пометки растёт с длиной нетронутого суффикса. При наличии `SKIPPED`
дополнительная работа разрешения этого промаха зависит от размера правки.
При ширине 1024 и 1, 2 или 4 обменах Quant сам обходится без пометки.
При 16, 32 или 128 обменах в этом окне проверка `SKIPPED` не срабатывает,
а средний широкий обход остаётся 760,5 ребра. Вывод относится к
промахам, на которых точный поиск возвращает уже помеченную пару.
Результат структурный. [Воспроизведение](./reorder-skipped.mjs)

проверку ответов выполняет существующий benchmark worker.

### Наблюдение только при индексировании

Узкий вариант оставляет `begin` и `take` исходными побайтно.
Он считает движения только при попадании в слот, уже доказавший пару.
В локальных измерениях работы `lb.shuffle@4096` и `mixed@512`
дают ноль регистраций, обёрток и ячеек вектора. На `deep-shuffle@4096`
после обучения сохраняется один векторный проход за шаг, с теми же
4097 ячейками и 4088 переносами. Границу хранения проверили на двух
соседних ширинах, 8193 ребра дают 8193 ссылки, 8194 дают ноль.

процесса. По хешам сборки Quant и первого вектора совпадают с предыдущей

На `deep-shuffle@4096` время сократилось на 9,5% на Xeon 8573C и
26,3% на EPYC 9V45. Порог 15% достигнут только во втором повторе.
На обоих раннерах зарегистрирован один обученный проход за шаг,
4097 рёбер в индексе и 4088 переносов. В этой ячейке ни одна из
сборок не зарегистрировала событий GC во время замеров. Одинаковые
структурные счётчики не объясняют различие в величине выигрыша.

Обычный shuffle и смешанный граф прошли порог 5%, счётчики обучения
в них нулевые. Из локальных контролей его превысил только
`stable.wide-256` на EPYC 9V74. Медиана там составляет 1,059
при A/A = 0,998 и нуле пробных проходов. Подобное замедление видно
на том же типе CPU в первой серии. Причину по этим замерам
установить нельзя. Узкий вариант остаётся исследовательской сборкой.

Выводы опираются на разные данные. Для плотной перестановки уже
индексируемого потребителя вектор снижает физическую цену обходов в двух
измеренных средах. Для нескольких вложенных обменов время наблюдения
можно вовсе исключить из решения о промахе, если точная связь уже
несёт свидетельство `SKIPPED`. Даже при одном и том же множестве
отношений эти режимы выигрывают от разных механизмов.

проверенные CI-артефакты в один читаемый JSON без объединения runner.
